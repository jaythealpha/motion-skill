## 1. 무엇이고 왜 만드는가

**한 줄:** 시간 바를 0에서 100으로 끌면 무언가가 변해 가는 과정을 정교한 입체 일러스트로 보여주는 Claude 스킬이에요. 첫 번째 렌즈는 **"제품이 분해된 상태에서 조립되는 과정"**이에요.

**왜:** 사용자는 colorfigures(손그림 느낌의 아이소메트릭 물체, 돌려 보고 버튼 누르기)를 분석했고, 그걸 고쳐 쓰는 게 아니라 **몇 단계 위의, 정체성이 다른 스킬**을 원해요. colorfigures의 중심은 "물체를 돌리고 누르기"예요. Unfold의 중심은 **"시간을 끌어서 변화를 보기"**예요. 결과물이 colorfigures를 베낀 것처럼 느껴지면 실패예요.

**보는 사람과 쓰임** (사용자가 말한 세 부류):
1. **구조가 궁금한 일반인**: "안이 이렇게 생겼구나" 하는 재미와 놀라움
2. **의미만 간단히 알고 싶은 사람**: 한 줄 요약, 핵심 부품 몇 개
3. **매뉴얼이 꼭 필요한 제조업체**: 정확한 조립 순서, 부품 수량과 규격, 인쇄 가능한 단계별 매뉴얼

사용자는 이 스킬로 만든 결과물을 바탕으로 제조업체의 협업이나 제작 의뢰를 받는 것도 염두에 두고 있어요. 그래서 결과물의 완성도가 곧 포트폴리오예요.

## 2. 목표, 하지 않을 것, 실패 기준

### 목표 (v1)
- 제품 **모델명**을 받으면 Claude가 공개 자료를 조사해 실제 부품 구성과 조립 순서로 **분해·조립 시간 바** 결과물을 만들어요.
- 시안보다 **훨씬 정교하고 전문적이며 정확해야** 해요. 사용자는 이걸 가장 강하게 요구했어요(3절).
- 0일 때의 배치 2가지 × 그림체 2가지를 자유롭게 조합해요(4절).
- 같은 결과물에서 보는 깊이를 **간단히 / 자세히 / 매뉴얼** 3단계로 바꿔요(5절).
- 자료로 확인한 부분과 추정한 부분을 화면에서 구분해서 보여줘요.
- v1은 **스마트폰이라면 어떤 모델이든** 모델명으로 만들 수 있는 과정(파이프라인)이에요. 그와 별개로 사람이 직접 다듬은 **완성 예제 1개**를 스킬에 넣어, 기준점이자 회귀 테스트로 써요. 2단계에서 TV와 사진 입력으로 넓혀요. *(Claude의 결정)*
- 파이프라인이 매번 40~80개 부품을 정확히 만들 수 있도록, 엔진은 **부품 형상 틀**(PCB, 배터리, 실드 캔, FPC 케이블, 나사, 커넥터, 카메라 모듈, 디스플레이 적층)을 제공하고 Claude는 치수와 위치만 채워요. *(Claude의 결정)*

### 하지 않을 것 (v1)
- 제조업체의 자체 자료(CAD, 부품표 파일) 입력은 하지 않아요. 다만 데이터 구조는 나중에 그걸 받을 수 있게 설계해요(7절).
- 다른 렌즈(노화, 원리, 시대 진화, 지역, 가상 세계)는 만들지 않아요. 엔진은 그 렌즈들이 올라올 수 있게 만들어요(10절).
- colorfigures의 색상 견본 선택기와 손그림 흔들림 슬라이더는 넣지 않아요(사용자가 줄여도 된다고 함).

### 실패 기준 (기술적으로 동작해도 실패)
- colorfigures를 다시 칠한 것처럼 보이는 경우
- 부품이 "상자 몇 개" 수준이라 전문가가 보기에 장난감 같은 경우
- 근거 없는 부품이나 순서를 사실처럼 보여주는 경우
- 부품이 다른 부품을 뚫고 지나가거나, 앞뒤 가림이 틀리거나, 공중에 떠 있는 경우
- 매뉴얼 단계가 실제 순서와 다른 경우

## 3. 정확도 기준

사용자가 말한 "정확하게"는 **실제 자료를 근거로 한다**는 뜻이에요.

**자료 출처** (우선순위 순):
1. 제조사 공식 규격표: 외형 치수, 무게, 배터리 용량, 칩 이름
2. 공개된 분해 리뷰와 수리 가이드(예: iFixit): 부품 목록, 분해 순서, 나사 종류와 개수, 커넥터, 접착 방식
3. 공개 인증 문서의 내부 사진(예: 전파 인증 기관 공개 자료), 공개된 서비스 매뉴얼
4. 위 자료가 다룬 부분을 바탕으로 한 추정 (추정으로 표시)

**부품 하나에 남길 정보:** 이름(한국어/영어), 분류, 치수, 위치, 무엇에 고정되는지, 고정 방식(나사 규격과 개수, 커넥터, 접착), 조립 단계, 출처 링크, **확인됨/추정** 표시.

**정밀도 목표** *(Claude의 제안, 빌더가 조정 가능)*:
- 스마트폰 기준 부품 40~80개. 나사, 커넥터, FPC 케이블, 실드 캔, 접착 테이프, 브래킷까지 포함해요.
- 외형 치수는 공식 수치와 ±0.5mm 이내로 맞춰요.
- 내부 부품의 위치와 크기는 분해 사진을 근거로 비례를 맞추고, 사진만으로 잰 값은 추정으로 표시해요.
- 부품 윤곽은 상자가 아니라 실제 모양이에요. 둥근 모서리, 절개부, 카메라 섬, 버튼 구멍, 배터리의 둥근 끝을 그려요.

**출처 자료의 사용 범위** *(Claude의 결정)*: 결과물은 상업적으로도 쓰일 수 있어요(포트폴리오, 제조업체 의뢰). 그런데 주요 출처인 iFixit 가이드는 비상업 라이선스(CC BY-NC-SA)예요. 그래서 출처의 사진, 그림, 문장을 결과물에 넣지 않아요. 사실(치수, 개수, 순서)만 참고하고, 그림과 설명은 Claude가 직접 만들고, 출처는 링크로만 밝혀요.

**조립 순서 = 분해 순서의 역순**이 기본이에요. 분해 가이드가 단계별로 있으면 그 단계를 그대로 따라요.

**결과물 안에 출처 패널**을 두고, 부품을 누르면 그 부품의 근거 자료와 확인됨/추정 여부를 보여줘요.

## 4. 화면 경험

### 4.1 시간 바
- 0 = 완전 분해, 100 = 조립 완료(제품이 켜진 상태). 바를 끌거나 재생 버튼으로 자동 진행해요.
- 바 위에 **조립 단계 표시**가 있어요. 단계마다 이름이 있고(예: "3. 배터리 장착"), 누르면 그 단계로 이동해요.
- 부품마다 바 위에서 자기 구간을 가져요. 구간은 조립 순서에서 자동으로 계산하고, 동시에 끼우는 부품은 같은 구간을 써요.
- 부품은 구간 동안 **실제 조립 경로**를 따라 움직여요. 예를 들어 커넥터는 마지막에 눌러 끼우고, 나사는 돌면서 들어가고, 디스플레이는 경첩처럼 접혀 닫혀요. 단순한 직선 이동만 있으면 안 돼요.
- 매뉴얼 모드에서는 바가 단계 단위로 맞춰져 멈춰요.

### 4.2 0일 때의 배치 (사용자가 2가지 모두 선택)
- **층층이 떠 있기 (Exploded stack):** 부품이 조립 축을 따라 층층이 떠 있어요. 같은 층의 부품은 옆으로 살짝 벌어져 겹치지 않아요.
- **매트 위 정렬 (Knolling):** 부품이 작업 매트 위에 종류별로 가지런히 놓여 있다가, 포물선을 그리며 날아와 조립돼요. 나사는 나사끼리 줄지어 놓여요.

### 4.3 그림체 (사용자가 2가지 모두 선택, 언제든 전환 가능)
- **컬러 일러스트:** 평면 색 음영에 외곽선이 있는 일러스트예요. colorfigures와 달라 보여야 해요. 손그림 흔들림 없이 깔끔한 선을 쓰고, 재질 표현(유리 반사, 금속 결, PCB 실크 인쇄)을 더 세밀하게 하고, 종이 질감 대신 자체 배경과 조명을 써요. 정확한 색감은 빌더가 정하되, 첫 시안에서 사용자 확인을 받아요.
- **설계도면:** 도면지 배경에 선으로 그려요. 번호 풍선, 조립 경로 점선, 치수선, 부품표(BOM), 도면 표제란이 있어요. 지금 움직이는 부품은 강조색으로 보여줘요.
- 그림체를 바꿔도 바의 위치와 카메라는 그대로예요.

### 4.4 카메라와 조작
- 드래그로 회전, 확대·축소가 돼요. 휴대폰에서도 동작해요.
- **자동 카메라** (기본 켬): 재생할 때 지금 조립 중인 부품 쪽으로 카메라가 부드럽게 다가가요. 사용자가 직접 돌리면 자동 카메라는 꺼져요.
- 부품에 마우스를 올리거나 탭하면 이름, 핵심 수치, 출처가 보여요.

### 4.5 라벨
- 라벨 연결선이 서로 교차하지 않아야 해요. colorfigures 분석에서 발견한 버그예요(`analysis/REPORT.md` A2).
- 휴대폰에서는 번호 배지로 바뀌고 이름 목록이 아래에 나와요.

## 5. 깊이 3단계 (보는 사람별)

결과물 상단에서 고르면 같은 모델이 그 깊이로 바뀌어요.

| | 간단히 | 자세히 (기본) | 매뉴얼 |
|---|---|---|---|
| 대상 | 의미만 알고 싶은 사람 | 구조가 궁금한 일반인 | 제조업체 |
| 부품 | 핵심 부품 5~8개만 강조, 나머지는 흐리게 | 전체 | 전체 + 나사·커넥터 개별 표시 |
| 라벨 | 핵심 부품 이름과 한 줄 설명 | 부품 이름 | 부품 번호(풍선) + 부품표 |
| 바 | 자동 재생 중심 | 자유롭게 끌기 | 단계 단위로 멈춤, 단계별 지시문 |
| 기본 그림체 | 컬러 | 컬러 | 설계도면 |

**매뉴얼 단계 하나에 담는 것:** 단계 번호와 제목, 장착할 부품과 수량, 고정 방식(예: "Phillips #000 나사 4개"), 주의사항(예: "배터리 커넥터는 마지막에 연결"), 그 단계의 정지 화면 1장.

## 6. 입력

- **v1:** 제품 모델명(예: "갤럭시 S24", "iPhone 15")
- **2단계:** 제품 사진. Claude가 사진에서 모델을 알아본 뒤 v1과 같은 과정을 거쳐요. 모델을 확신할 수 없으면 후보를 보여주고 고르게 해요.
- **스킬은 다른 사람들이 설치해서 직접 써요. 중간 확인 없이 혼자 끝까지 가야 해요** (사용자 결정). 그래서 사람이 검토하는 대신 9절의 자동 점검이 품질을 지켜요.
- 공개 자료가 부족한 모델이어도 멈추지 않아요. 그 대신 결과물 맨 위에 확인된 부품의 비율을 보여주고(예: "부품 62% 자료 확인 · 38% 추정"), 비율이 기준(빌더가 정함, 예: 50%)보다 낮으면 눈에 띄는 경고 띠를 붙여요. 모델명이 모호하면 가장 유력한 모델로 진행하고, 어떤 모델로 해석했는지 결과물에 밝혀요. *(Claude의 결정)*

## 7. 데이터 구조 (렌더링과 분리)

조사 결과는 **조립 모델(JSON)** 하나로 정리하고, 화면은 이 데이터만 읽어서 그려요.

이유는 두 가지예요.
- 나중에 제조업체 자체 자료(부품표 CSV, CAD에서 내보낸 형상)를 같은 구조로 변환해 넣을 수 있어요.
- 같은 데이터로 화면, 매뉴얼 PDF, 다른 렌즈를 모두 만들 수 있어요.

**최소 구성** *(필드 이름은 빌더가 정함)*:
- `product`: 모델명, 제조사, 외형 치수, 출처
- `parts[]`: 3절의 부품 정보 + 형상(윤곽 프로필, 두께, 둥근 모서리, 구멍)
- `steps[]`: 순서, 제목, 장착할 부품, 고정 방식, 주의사항, 조립 경로 종류
- `sources[]`: 링크, 제목, 무엇의 근거인지

## 8. 만드는 방식 (Claude의 결정, 사용자 승인 전)

- **새 엔진을 만들어요.** colorfigures의 `core.js`를 이어 쓰지 않아요. 분석에서 찾은 가장 큰 약점은 깊이 버퍼가 없어 앞뒤 가림을 손으로 정렬해야 한다는 거였어요(REPORT C1). 부품이 수십 개면 이 방식으로는 정확도를 지킬 수 없어요.
- **권장:** WebGL(three.js)에 깊이 버퍼를 쓰고, 평면 음영 + 외곽선 후처리로 일러스트 느낌을 내요. 설계도면은 같은 장면을 선 렌더링으로 그려요. 라이브러리는 결과물 안에 포함해서 인터넷 없이도 열리게 해요. 다른 방식이 정밀도, 그림체, 파일 크기 면에서 낫다면 빌더가 근거를 들어 바꿔도 돼요.
- **스킬이 돌아가는 환경:** Claude Code(인터넷 조사 가능, Node·Python, 헤드리스 크롬 사용 가능). 조사와 검증은 만드는 시점에 이 환경에서 해요. 설치한 사람의 환경에 크롬이 없으면 관문 2(화면 점검)는 건너뛰고 그 사실을 결과물에 적되, 관문 1(데이터 점검)은 항상 실행해요. *(Claude의 결정)*
- **결과물:** 혼자 열리는 HTML 파일 1개(colorfigures처럼). 데스크톱과 휴대폰을 모두 지원해요.
- **내보내기:** 무거운 인코더를 HTML에 넣지 않고, 브라우저 기본 기능으로 해요. 정지 이미지는 PNG로 저장하고, 시간 바 재생 영상은 브라우저 녹화(WebM)로 만들어요. 매뉴얼은 인쇄용 화면을 따로 두고 브라우저의 "PDF로 저장"을 써요. 단계별 페이지에 설계도면 그림체를 써요. 고품질 MP4나 PDF 파일은 만드는 시점에 헤드리스 크롬으로 함께 생성할 수 있어요(선택). *(Claude의 결정)*
- **언어:** UI와 라벨은 한국어가 기본이고, 영어로 전환할 수 있어요.
- **스킬 구성:** SKILL.md(작업 순서, 조사 방법, 정확도 기준, 검증 방법), 엔진, 빌드 스크립트, 완성 예제 1개 이상

## 9. 검증

사람이 중간에 확인하지 않으므로, 검증은 **스킬이 스스로 실행하고 통과해야 다음 단계로 가는 관문**이에요. 관문을 통과하지 못하면 Claude가 고치고 다시 돌려요(최대 횟수는 빌더가 정함). 끝까지 통과하지 못한 항목은 결과물의 "알려진 한계" 목록에 적어요.

**관문 1: 조사 데이터 점검 (그림 그리기 전, 스크립트로 자동 실행)**
- 모든 부품에 출처 링크나 "추정" 표시가 있는가
- 외형 치수가 공식 규격과 ±0.5mm 이내인가
- 모든 부품이 고정 대상과 고정 방식을 가지는가(떠 있는 부품 없음)
- 모든 부품이 정확히 한 단계에 속하고, 단계 순서가 분해 가이드의 역순과 맞는가
- 부품끼리 조립 완료 상태에서 서로 겹치지 않는가(형상 교차 검사)
- 내부 부품이 외곽 안에 들어가는가

**관문 2: 화면 점검 (헤드리스 크롬)**
- 아래의 정지 화면과 충돌 점검을 통과하는가
- 스크립트 오류가 없는가

colorfigures 분석에서 찾은 검증 방법의 결함(REPORT B1~B3)도 고쳐서 넣어요.
- **휴대폰:** 창 크기만 바꾸는 방식이 아니라 실제 모바일 에뮬레이션으로 확인해요.
- **바 위치별 정지 화면:** 0, 25, 50, 75, 100 위치와 단계별 정지 화면을 찍어 한 장으로 모아 봐요. 애니메이션 때문에 멈추지 않게, 바 위치를 직접 지정하는 URL 파라미터를 써요.
- **정확도 점검표:** 모든 부품에 출처나 추정 표시가 있는지, 외형 치수가 공식 수치와 맞는지, 조립 순서가 분해 가이드의 역순인지, 모든 부품이 무언가에 고정되어 있는지 확인해요.
- **충돌 점검:** 0과 100 사이를 움직이는 동안 부품끼리 뚫고 지나가지 않는지 자동으로 확인해요.

## 10. 이후 로드맵 (v1 범위 아님, 엔진이 받아들일 수 있어야 함)

모두 "0~100 시간 바"라는 같은 틀 위에 올라가요.
1. **2단계:** TV, 사진 입력
2. **하루·노화 렌즈:** 낮과 밤의 빛 변화, 새 제품에서 10년 쓴 모습까지(먼지, 변색, 배터리 부풂)
3. **원리 렌즈:** 원리나 프롬프트로 설명한 과정을 모션으로 보여줘요
4. **시대 진화 렌즈:** 예를 들어 비둘기 → 전보 → 유선 전화 → 휴대폰
5. **지역 변천 렌즈:** 같은 장소의 수십 년 변화
6. **가상 세계:** 여러 물체와 건물이 모인 디오라마
7. **Claude의 추가 제안:** 두 제품을 같은 바에 나란히 놓는 비교, 확대해 들어가는 스케일 렌즈, 원자재부터 재활용까지의 수명 렌즈
8. **제조업체 자체 자료 입력과 제작 의뢰용 기능**
