# Unfold v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Unfold Claude skill: given a smartphone model name, Claude researches public teardown data, writes an assembly model (JSON), passes two automatic gates, and ships one self-contained HTML page where a 0–100 time bar assembles the phone from its parts.

**Architecture:** Pure, Node-testable ES modules (model validation, part geometry boxes, layouts, timeline) are shared by the browser renderer and the Gate 1 checker. The browser layer uses three.js (depth buffer, orthographic camera) with two styles (color illustration, blueprint) built from the same meshes. A no-bundler build inlines three.js and every engine module as `data:` URLs in an import map, plus the model JSON, into one HTML file.

**Tech Stack:** JavaScript ES modules, three.js (pinned, vendored), Node 24 (`node:test`, global `WebSocket` for CDP), headless Google Chrome (Gate 2), no other runtime dependencies.

**Spec:** `docs/specs/2026-10-28-unfold-design.md`

## Global Constraints

- Output = one self-contained HTML file that works offline. No requests to other hosts.
- UI and labels are Korean by default. `?lang=en` switches to English.
- No colorfigures look: no palette picker, no wobble slider, no paper texture. Clean lines and a studio background in the color style.
- Official outer dimensions must match the model within ±0.5 mm (Gate 1 error otherwise).
- Phone models target 40–80 parts (Gate 1 warning outside that range).
- Every part has `sourceIds` (≥1) or `confidence: "estimated"`. The page shows the verified share, and adds a warning band below 50%.
- No source photos, drawings or sentences in any output. Facts only, written in our own words. Sources appear as links.
- Unattended: gates loop at most 3 rounds, then remaining failures go to `meta.limitations` and are shown on the page.
- The skill runs in Claude Code. Without Chrome, Gate 2 is skipped (and stated on the page), but Gate 1 always runs.
- No git commits (the user did not ask for them).

## Review Focus

1. **A model that is mostly estimated** (e.g., 20% verified): the page still renders, the banner shows the share, and the warning band appears. Test: `model.test.mjs › verifiedShare + warn flag`.
2. **Broken references** (an `attachedTo` or a step part id that doesn't exist, a part in no step): Gate 1 names the part and the field and exits 1. Never crash. Test: `check_model.test.mjs › broken refs`.
3. **Scrubbing while playing, or switching layout mid-play:** the scene is a pure function of `t` + options, so the same `t` always gives the same pose. Test: `timeline.test.mjs › pure and endpoints`.
4. **375 px phone viewport:** no horizontal scroll, every control reachable. Gate 2 asserts `scrollWidth <= innerWidth` under real device emulation.
5. **Long part names** (Korean and English, 40+ characters) in labels, the BOM and step cards: text wraps or ellipsizes and never overflows its box. Test fixture `long-names.json` is shot by Gate 2 in manual depth.

## Shared interfaces (all tasks use these names)

- **Coordinates:** mm. Phone screen-down on the table. `x` = width (0 = left edge seen from the back), `y` = length (0 = USB-C end), `z` = thickness (0 = front glass, increasing toward the back). Assembly goes in +z.
- **Model** (after `normalizeModel`): `{ product:{name, maker, dims:{w,l,t}, ...}, sources:[{id,title,url,covers}], parts:[Part], steps:[Step], meta:{limitations:[], researchedAt, gate2} }`.
- **Part:** `{ id, name:{ko,en}, category, count, bbox:[x0,y0,z0,x1,y1,z1], shape:{template, ...params}, attachedTo, fastening, step, sourceIds:[], confidence:'verified'|'estimated', key:boolean, desc:{ko,en}, notes }`.
- **Step:** `{ n, title:{ko,en}, parts:[id], tools, cautions:{ko,en}, path:'drop'|'screw'|'press'|'slide'|'fold' (default 'drop'), sourceIds }`.
- **Templates (`shape.template`):** `box`, `plate` (`r` corner radius, `holes:[[cx,cy,w,h,r]]`), `housing` (`r`, `wall`, `floor`: outer frame + display as one base), `ring` (`r`, `wall`: frame walls only), `pcb` (`r`, `chips:[[x0,y0,x1,y1,h,color]]`), `battery` (`r`), `shield` (`r`), `screw` (`head`, `len`; `count` instances at `positions:[[x,y]]`), `connector`, `flex` (`path:[[x,y,z]...]`, `width`), `camera` (`lenses:[[cx,cy,r]]`), `coil` (`rIn`, `rOut`), `speaker` (`r`), `motor`, `button`, `port`, `adhesive` (`r`).
- **Pose:** `{ pos:[dx,dy,dz], rot:[rx,ry,rz] (radians, about the part centre), progress:0..1, active:boolean }`.

### Task 2: Part geometry (pure boxes + three.js meshes)

**Files:** Create `unfold/engine/shapes.js`, `unfold/tests/shapes.test.mjs`

**Interfaces:**
- Consumes: Part from Task 1.
- Produces: `partBoxes(part) -> [{min:[x,y,z], max:[x,y,z]}]` in model coordinates: `housing` → floor slab + 4 walls; `ring` → 4 walls; `screw` → one small box per position; everything else → its bbox. `buildPartMesh(THREE, part) -> THREE.Group` with `userData.partId`, every child mesh carrying `userData.partId` and a `userData.role` of `'body'|'detail'`. Geometry comes from `THREE.Shape` rounded-rect profiles with holes, extruded along z. Pcb chips are boxes, camera lenses are cylinders with a dark glass disc and a metal ring, screws are a head cylinder with a cross slot plus a shank, the coil is concentric torus-like rings on a sheet, a flex is a flat ribbon swept along its path, a speaker has a grille slot pattern, and the battery has rounded ends and a label inset.

### Task 3: Layouts and timeline (pure)

**Files:** Create `unfold/engine/layout.js`, `unfold/engine/timeline.js`, `unfold/tests/timeline.test.mjs`

**Interfaces:**
- Consumes: Model, `partBoxes`.
- Produces:
  - `stackLayout(model, {gap=14}) -> Map(partId -> [dx,dy,dz])`: start offset in +z. Each step `k` floats `gap*rank(k)` above the top of the assembled phone. Parts in the same step whose x/y footprints overlap get extra `+gap/2` each, in order.
  - `knollLayout(model, {margin=8}) -> Map(partId -> {pos:[dx,dy,dz], rot:[0,0,rz]})`: the step-1 base stays home. Every other part lies flat on the table (`z0 → 0`) in a grid to the +x side of the phone, rows ordered by step, shelf-packed with `margin` and no footprint overlap. Screws of a step sit in one row.
  - `stepWindows(model) -> Map(stepN -> [t0,t1])`: covers `[0, 96]` in step order, weighted by `1 + 0.35*partsInStep`. `[96,100]` is the finale.
  - `partPose(model, part, t, layout, starts) -> Pose`: progress `p` = eased local time within the part's window, staggered by index inside its step (`stagger = 0.12` of the window). Path rules: `drop` = straight; `screw` = last 40% spins 3 full turns about z; `press` = overshoot by 0.6 mm in −z at 85–95% then settle; `slide` = start offset along +y instead of z; `fold` = rotate about the part's x-axis edge. Knoll adds an arc lift of `25 * sin(πp)` mm.
  - `finalePose(t) -> {flip:0..1, screenOn:boolean}`: the flip eases over 96–99.5, the screen turns on at ≥99.5.
- [ ] **Step 1: Failing tests:** `windows cover 0..96 in order, no gaps`; `pure and endpoints` (pose at t=0 equals the layout start, pose at t=100 is zero offset, and calling twice with the same args gives deep-equal poses); `knoll footprints do not overlap` (pairwise on `mini.json`); `stack start is above the assembled top`; `screw spins only in the last 40%`.
- [ ] **Step 2:** Run → FAIL. **Step 3:** Implement. **Step 4:** Run → PASS.

### Task 4: Renderer and styles

**Files:** Create `unfold/engine/render.js`, `unfold/engine/i18n.js`, `unfold/scripts/dev.html`

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces: `createRenderer(canvas, model, {style, layout}) -> R` with
  - `R.setStyle('color'|'blueprint')`, `R.setLayout('stack'|'knoll')`, `R.setT(t)` (applies poses + finale; pure in `t`)
  - `R.setDepth('simple'|'detail'|'manual')` (simple dims non-key parts to 0.18 opacity)
  - `R.orbit(dyaw, dpitch)`, `R.zoom(k)`, `R.setAuto(bool)` (auto camera eases its target to the active step's centroid)
  - `R.project(partId) -> {x,y,visible}` (screen anchor for labels), `R.pick(clientX, clientY) -> partId|null`, `R.snapshot(scale) -> Promise<Blob>`, `R.dataURL(t, opts) -> string`
  - `R.onFrame(fn)`
- Styles. **Color:** `MeshToonMaterial` with a 3-step gradient map, material per category (glass `#1f2a36`, aluminium `#c9ced6`, pcb `#2e7d5b`, battery `#f2c14e` with a grey label, copper coil `#c8794b`, flex `#d9a441`, black parts `#2b2d31`, screws `#9aa1aa`), crisp ink edges via `EdgesGeometry(30°)` in `#1b1d22` at 1 px, a studio background gradient `#eef1f5 → #dde3ea`, and a soft contact shadow (radial-gradient texture) under the phone. **Blueprint:** background `#0f3460` + CSS grid; meshes become fills in `#123d70` with polygon offset, edges `#e6f0ff`; active-step edges `#ffd23f`.
  - Camera: orthographic, default yaw 35°, pitch 32°, framed on the union of the bounds at t=0 and t=100 for the current layout.

### Task 5: Page UI, labels, panels, exports, print manual

**Files:** Create `unfold/engine/ui.js`, `unfold/engine/main.js`

**Interfaces:**
- Consumes: `createRenderer`, `i18n.t`, model helpers.
- Produces: `mountUnfold(rootEl, model, params)`. URL params: `t, layout, style, depth, step, lang, yaw, pitch, auto, play`. Exposes `window.__unfold = { R, model, state, errors }`.
- UI:
  - **Top bar:** product name · banner "부품 N개 · 자료 확인 X% · 추정 Y%" (warning band when below 50%) · the model interpretation note.
  - **Toggles:** depth (간단히/자세히/매뉴얼), layout (층층이/매트 정렬), style (컬러/도면), language.
  - **Time bar:** range 0–100 with step ticks (titles on hover), play/pause, current step "3/12 · 배터리 장착". In manual depth it snaps to step ends.
  - **Labels:** an SVG leader layer plus HTML pills for the active step's parts (detail), key parts with a one-line desc (simple), or numbered balloons (manual). Pills on each side are sorted by anchor y, and a side is chosen by the anchor's x relative to the canvas centre. Max 8 visible.
  - **Part popover** on click/tap: name, size, fastening, confidence badge, source links.
  - **Sources panel:** source list, the known limitations, and the Gate 2 status.
  - **Manual depth:** a step card (title, parts with counts, tools, cautions) and a BOM table.
  - **Exports:** PNG (`R.snapshot(2)`), video (WebM via `canvas.captureStream(60)` + `MediaRecorder`, playing 0→100 in 10 s), print manual (build a print-only section with one `R.dataURL(stepEnd, {style:'blueprint'})` image per step plus its step card, then `window.print()`).
  - **Mobile (≤ 600 px):** controls stack under the canvas, the bar is full width, labels become numbered badges with a list under the canvas.

### Task 6: Gate 1, Gate 2, single-file build

**Files:** Create `unfold/scripts/check_model.mjs`, `unfold/scripts/shoot.mjs`, `unfold/scripts/build.mjs`, `unfold/tests/check_model.test.mjs`

**Interfaces:**
- `node scripts/check_model.mjs <model.json> [--official w,l,t] [--json]`: runs `validateModel`, then **collision**: (a) at t=100, every pair of `partBoxes` that intersect by more than 0.05 mm on all axes, skipping pairs where one is `attachedTo` the other or either part is a `fastener`/`adhesive`/`flex`; (b) along the stack path at t ∈ {10..95 step 5}, moving parts against already-seated parts, with the same exclusions. Exits 1 on errors and prints `GATE1 PASS|FAIL errors=N warnings=M verified=XX%`.
- `node scripts/build.mjs <model.json> <out.html> [--gate2 pass|skipped|fail]` → one HTML: an import map whose `three` and `unfold/*.js` entries are base64 `data:` URLs, the model embedded in `<script type="application/json" id="unfold-model">`, inline CSS, and `<script type="module">import 'unfold/main.js'</script>`. It fails if the output references any `http(s)://` script or style.
- `node scripts/shoot.mjs <page.html> <outDir>`: launches Chrome (`--headless=new --remote-debugging-port=0`, reads the port from stderr), drives CDP over the global `WebSocket`, and shoots t ∈ {0,25,50,75,100} × layout {stack,knoll} × style {color,blueprint} at 1280×860, plus manual-depth step shots and one mobile shot (`Emulation.setDeviceMetricsOverride` 375×812, dpr 2, mobile true). It asserts `scrollWidth <= innerWidth` on mobile and `__unfold.errors.length === 0` on every shot, writes `contact.html` + `contact.png`, prints `GATE2 PASS|FAIL`, and exits 2 with `GATE2 SKIPPED` when Chrome is not found.
- [ ] **Step 1: Failing tests:** `check_model passes mini`, `check_model fails broken with named fields` (spawn the script, assert exit code and output), `collision detected` (a fixture with two overlapping plates).
